# Задача: заново реализовать страницу «Отчеты по сотрудникам» в TaskFlow

Нужно заново спроектировать и реализовать страницу отчетов сотрудников в существующем проекте TaskFlow.

В качестве основного визуального референса используй приложенный скриншот.

ВАЖНО: на референсе присутствуют блоки:

- «Проблемы / Блокеры»
- «Договоренности / Планы»

ИХ РЕАЛИЗОВЫВАТЬ НЕ НУЖНО.

Полностью убрать эти два блока из нового интерфейса.

---

# 1. Сначала изучи существующий проект

Перед написанием кода проанализируй frontend и backend проекта.

Найди:

- текущий layout;
- sidebar;
- header;
- routing;
- UI-kit / компоненты;
- используемую библиотеку иконок;
- стили;
- API/service слой;
- модели сотрудников;
- отчеты;
- Jira-задачи;
- Git-отчеты;
- видеоотчеты.

Не создавай отдельную дизайн-систему.

Новая страница должна выглядеть как естественная часть существующего TaskFlow.

Максимально переиспользуй существующие:

- Button
- Select
- Input
- Card
- Tabs
- DatePicker
- Avatar
- Badge
- Skeleton
- Modal/Drawer

если они уже существуют.

Не подключай новую UI-библиотеку без необходимости.

---

# 2. Что представляют собой отчеты

В TaskFlow есть ТРИ разных источника отчетности сотрудника:

1. Git-отчет
2. Отчет по задачам / Jira
3. Видеоотчет

ВАЖНО:

Git-отчет — это НЕ список коммитов и НЕ количество коммитов.

Backend уже возвращает сформированный дневной текстовый отчет.

Пример:

{
"Успех": true,
"Ошибка": "",
"Сотрудник": "Элдос Уланбеков Уланбекович",
"Дата": "10.09.2026",
"Отчет": "Всего отработано 9 ч. (10.09.2026)..."
}

Внутри Git-отчета могут содержаться:

- количество отработанных часов;
- проекты;
- статистика изменений;
- описание того, чем занимался сотрудник;
- новые задачи;
- выполненные задачи;
- дополнительный текст.

НЕ считать количество commits самостоятельно.

НЕ использовать количество commits как KPI.

НЕ создавать productivity score.

---

# 3. Видеоотчет

Видеоотчет представляет собой видео сотрудника в конце рабочего дня.

Кроме самого видео, backend может предоставлять текстовое представление / расшифровку того, что сотрудник рассказал на видео.

На UI нужно показывать:

- есть видео или нет;
- дату;
- время;
- продолжительность, если доступна;
- кнопку просмотра видео;
- текстовую расшифровку / текстовое содержание видео.

Не придумывать содержание видео на frontend.

Если текст отсутствует, показать только информацию о наличии видео.

# 6. Фильтры

Следующая строка:

[ Поиск сотрудника ]

[ Отдел ]

[ Сотрудник ]

и быстрый период:

[ Этот месяц ]

Также должен быть выбор произвольного диапазона дат.

Все фильтры должны работать совместно.

# 13. Краткая сводка дня

Большая карточка:

«Краткая сводка дня»

Пример содержимого:

Занимался обменом валют в POS-терминале и веб-интерфейсе.
Делал перевод веб-интерфейса.
Формировал отчеты Telemedia по одному сотруднику.
Тестировал миграцию в новую базу.

Это должен быть нормальный читаемый текст.

Не показывать пользователю сырой JSON.

Если backend пока возвращает одну строку "Отчет", создать parser/service слой отдельно от UI.

UI-компоненты не должны самостоятельно парсить огромную строку.

# 14. Проекты и изменения

telemedia-admin

-280 529

telemedia-app

+722
-288

Положительные/отрицательные изменения визуально различать.

Но НЕ интерпретировать большое количество измененных строк как хорошую или плохую работу.

Это просто техническая информация.

# 15. Задачи

Следующий большой блок:

«Задачи»

Показывать информацию из Jira и/или сформированного отчета.

Если новых задач нет:

Новых задач нет

Если выполненных нет:

Выполненных задач нет

Если задачи имеются, показывать нормальными строками/карточками:

TASK-142
Добавить страницу отчетов
Done

TASK-143
Исправить синхронизацию
In Progress

Если есть Jira URL — Jira Key сделать кликабельным.

Использовать существующие Jira status badges проекта.

и

«Договоренности / Планы»

НЕ пытаться автоматически извлекать договоренности.

После блока проектов пространство использовать для более удобного отображения:

- задач;
- краткой сводки;
- видеоотчета.

# 18. Текст видеоотчета

Рядом или под видео:

«Текст видеоотчета»

Показывать текст, который backend получил из видео.

Например:

Сегодня работал над обменом валют в POS-терминале.

Продолжил перевод веб-интерфейса.

Тестировал миграцию базы данных.

Обсудили дальнейшее тестирование после увеличения мощности сервера.

Если текста много:

показывать первые несколько строк.

Кнопка:

«Показать полностью»

При нажатии раскрывать весь текст или открывать Drawer/Modal — используй тот паттерн, который уже есть в проекте.

Не подписывать это как AI, если пользователь этого видеть не должен.

Можно просто:

«Текст видеоотчета»

# 25. Service layer

Вынести работу с API отдельно.

Примерно:

reportsService.getJiraReport(employeeId, filters)

reportsService.getVideoReport(employeeId, date)

reportsService.getReportsSummary(filters)

Если endpoint уже существует — использовать существующий.

Не создавать duplicate endpoints без необходимости.

---

# 26. Parser Git-отчета

Так как Git API сейчас может возвращать большой текст:

{
"Сотрудник": "...",
"Дата": "...",
"Отчет": "..."
}

НЕ размазывать regex/string parsing по React-компонентам.

Создать отдельный parser/adapter.

Например:

parseGitReport(rawReport)

который возвращает UI-friendly структуру примерно:

{
employee,
date,
workedHours,
projects,
workSummary,
newTasks,
completedTasks,
raw
}

Если надежно распарсить какое-либо поле невозможно — сохранить его в raw/summary.

НЕ придумывать данные.

---

# 27. Очень важные ограничения

Не делать:

❌ количество commits;

❌ рейтинг сотрудников;

❌ «лучший сотрудник»;

❌ productivity score;

❌ эффективность на основании commits;

❌ проблемы / блокеры;

❌ договоренности / планы;

❌ выдуманные AI-данные;

❌ fake percentages;

❌ mock data в production-коде после подключения API.

Страница должна отвечать на вопрос:

«Что происходило с работой этого сотрудника за выбранный день или период и какие отчеты по нему доступны?»

---

# 28. Дизайн

Максимально ориентироваться на приложенный референс:

- светлый SaaS UI;
- существующий sidebar TaskFlow;
- белый/светлый background;
- аккуратные cards;
- небольшие borders;
- мягкие shadows;
- умеренный border radius;
- фиолетовый primary accent;
- зеленый для успешных состояний;
- красный только для ошибок/отсутствующего обязательного отчета;
- много whitespace;
- компактные filters;
- четкая типографическая иерархия.

Не копировать ошибочные элементы референса.

В частности удалить:

Проблемы / Блокеры
Договоренности / Планы

Освободившееся пространство использовать для увеличения:

«Краткая сводка дня»

«Проекты и изменения»

«Задачи»

и особенно:

«Видеоотчет + текст видеоотчета»

---

# 29. Перед реализацией

Сначала дай короткий analysis существующего проекта:

- найденные компоненты;
- API;
- routes;
- data models;
- что можно переиспользовать;
- какие файлы потребуется изменить.

После этого сразу приступай к реализации.

Не останавливайся после анализа и не жди моего подтверждения, если нет критической неоднозначности.

---

- build;
- TypeScript;
- lint;
